# C 자료구조 로컬 커뮤니티 시뮬레이터 개발 WBS

> 기간: 2026-08-12 ~ 2026-08-30
> 기준 시간: 하루 평균 6시간 + α
> 프로젝트 목표: 직접 구현한 C 자료구조를 사용하는 raylib 기반 로컬 커뮤니티 데스크톱 앱 제작
> 버퍼: 3일 확보

## 1. 프로젝트 개요

### 프로젝트명

C Community Simulator

### 한 줄 설명

회원이 가입·로그인한 뒤 글과 계층형 댓글을 작성하고, 좋아요/싫어요 반응과 제목 검색을 이용할 수 있는 단일 PC용 커뮤니티 데스크톱 앱이다.

### 핵심 목적

서버 기반 커뮤니티를 모방하는 것이 아니라 C의 포인터·동적 메모리·파일 입출력과 자료구조를 실제 화면 기능에 연결하는 학습 프로젝트다.

- 데이터와 자료구조는 C 코어가 책임지고, raylib는 입력과 표시만 담당한다.
- 모든 동적 할당 모듈은 대응하는 해제 함수를 제공한다.
- 기능별 정상·경계·실패 경로를 테스트하고 적용 이유와 복잡도를 문서화한다.

### 2.2 확정 업무 규칙

- 로컬 단일 프로그램이다. 네트워크, 서버, 다중 PC 동기화는 하지 않는다.
- 아이디는 고유하며, 회원가입 시 중복을 검사한다.
- 글·댓글의 수정과 삭제는 작성자 본인만 가능하다.
- 회원 탈퇴 시 계정을 물리 삭제하지 않고 WITHDRAWN 상태로 바꾼다. 기존 글·댓글의 작성자 표시는 탈퇴 회원으로 한다.
- 글을 삭제하면 해당 글의 댓글·반응과 이후 확장 데이터(투표)를 함께 제거한다.
- 대댓글이 있는 댓글을 삭제하면 본문 대신 '삭제된 댓글입니다.'만 남기고 대댓글은 유지한다. 대댓글이 없는 댓글은 제거할 수 있다.
- 반응은 최초 NONE이며 한 번 반응한 뒤 취소해 NONE으로 되돌릴 수 없다. LIKE와 DISLIKE 사이 변경은 가능하다.
- 글과 댓글 텍스트는 줄바꿈과 쉼표를 허용하지 않고 길이 상한을 둔다. 정확한 상한은 ADT 설계에서 상수로 확정한다.
- 비밀번호 원문은 CSV·로그·문서에 저장하지 않는다. password_hash 필드의 저장 방식은 구현 전에 확정하며, 이 앱을 보안 제품으로 주장하지 않는다.

### 2.3 이번 MVP에서 하지 않을 것

- 네트워크 통신, 서버, DBMS, 웹 프론트엔드, 실제 보안 인증
- 팔로우·친구 관계와 일반 그래프 시각화
- 투표, 알림, 첨부 파일, 관리자 기능
- 여러 단계보다 깊은 대댓글
- 완성도 높은 상용 GUI·접근성 기능

### 2.4 2차 확장 후보

| 항목 | 진입 조건 |
|---|---|
| 투표 | F-01~F-10, CSV, raylib UI와 테스트가 모두 안정화된 경우 |
| 스택/큐/일반 그래프 | 커뮤니티 MVP와 무관하게 별도 학습 모듈을 만들 시간이 확보된 경우 |
| 해시 테이블 검색 색인 | 글 수 증가로 선형 탐색의 한계를 확인한 경우 |
| Unity Engine 연동 | raylib MVP 완료 후 C 코어를 DLL 경계로 분리할 별도 2차 일정 확보 |
| Unity Test Framework | assert 기반 테스트가 안정화되고 도입 시간이 남는 경우 |

## 3. 프로젝트 구조와 자료구조 방향

### 3.1 예정 디렉터리 구조

아래 구조는 8/30 MVP 구현을 위한 목표 구조다. 현재 문서 단계이므로 아직 없는 파일은 구현 일정에 맞춰 만든다. `raylib` 화면 코드는 `src/ui/`에 두고, 자료구조·업무 규칙·CSV 처리는 `src/core/`와 `src/storage/`에 분리한다.

~~~text
.
├── README.md
├── CMakeLists.txt                  # raylib를 연결할 빌드 설정(8/13 계획)
├── include/
│   ├── common/                     # 반환 코드, 상수, 입력 검증
│   ├── domain/                     # Member, Post, Comment, Reaction 구조체/열거형
│   ├── core/                       # 동적 배열 ADT와 회원·인증·글·댓글·반응 API
│   ├── storage/                    # CSV 형식과 저장·불러오기 API
│   └── ui/                         # 화면 상태와 raylib UI API
├── src/
│   ├── main.c                      # 앱 초기화, 종료, 화면 루프 진입점
│   ├── common/                     # 오류 코드와 공통 유틸리티 구현
│   ├── domain/                     # 도메인 기본값, 상태 전이 보조 구현
│   ├── core/                       # 자료구조와 업무 규칙 구현
│   ├── storage/                    # members/posts/comments/reactions CSV 구현
│   └── ui/                         # 로그인·목록·상세·편집·프로필 raylib 화면
├── tests/
│   ├── core/                       # ADT·업무 규칙 assert 단위 테스트
│   └── storage/                    # CSV 정상·경계·실패 경로 테스트
├── data/
│   └── sample_*.csv                # 버전 관리하는 데모 데이터만 보관
└── docs/
    ├── learning/                   # 독립 자료구조 학습 로드맵·학습 기록
    ├── project/                    # WBS, ADT, 모듈, CSV, 화면 흐름 설계
    ├── daily-log/                  # 날짜별 기획·개발 기록(개인 작업 기록)
    └── verification/               # 테스트 계획·결과, 복잡도, 메모리 점검
~~~

### 3.2 모듈 책임

| 영역 | 책임 | 대표 적용 자료구조/규칙 |
|---|---|---|
| `domain` | 엔터티와 상태를 선언한다. | `Member`, `Post`, `Comment`, `Reaction`, `ReactionStatus` |
| `core/member`, `core/auth` | 회원가입, 아이디 중복 검사, 로그인·로그아웃, 정보 수정·탈퇴 처리를 맡는다. | 동적 배열, 선형 탐색, 탈퇴 시 `WITHDRAWN` 상태 |
| `core/post` | 글 작성·조회·수정·삭제와 작성자 권한을 처리한다. | 동적 배열, ID 탐색, 삭제 시 하위 데이터 정리 |
| `core/comment` | 댓글·대댓글 한 단계와 삭제 표시 규칙을 처리한다. | `parent_comment_id` 기반 계층 순회 |
| `core/reaction` | 글당 사용자별 반응 하나와 집계를 관리한다. | `NONE → LIKE/DISLIKE`, `LIKE ↔ DISLIKE`만 허용 |
| `core/search_sort` | 제목 부분 검색과 목록 정렬을 제공한다. | 선형 탐색, 비교 함수 기반 정렬 |
| `storage` | 4개 CSV의 저장·불러오기와 참조 무결성을 확인한다. | 회원 → 글 → 댓글 → 반응 순서 복원 |
| `ui` | 화면 입력을 C 코어 API에 전달하고 결과·오류를 표시한다. | 화면 상태 전환, 코어를 직접 우회하지 않음 |

| 자료구조/개념 | 프로젝트 적용 | MVP 여부 |
|---|---|---|
| 동적 배열 | 회원·글·댓글·반응 목록 보관 | 필수 |
| 부모 ID 기반 트리 | 댓글과 한 단계 대댓글 표현·들여쓰기 출력 | 필수 |
| 선형 탐색 | 아이디 중복 검사, ID 탐색, 제목 부분검색 | 필수 |
| 정렬 | 최신순, 좋아요/싫어요 집계 기반 목록 | 필수 |
| 힙/우선순위 큐 | 인기 글 Top N | 핵심 기능 안정화 후 적용 |
| 연결 리스트 | 댓글 자식 목록 또는 별도 학습 구현 | 선택 |
| 스택·큐·일반 그래프 | 별도 2차 학습/기능 확장 | 제외 |

## 4. 개발 규칙

1. 기능은 C 코어 API와 단위 테스트를 먼저 만들고 raylib UI에서 호출한다.
2. UI가 CSV를 직접 읽거나 목록을 직접 조작하지 않는다.
3. 오류는 반환 코드로 전달하고 UI는 사용자용 메시지로 변환한다.
4. 문자열 길이·금지 문자·로그인 상태·작성자 권한을 모든 입력 경로에서 검증한다.
5. 저장 전에 메모리 상태가 유효해야 하며, 불러오기 실패 시 부분 데이터가 남지 않게 한다.

## 6. 검증과 리스크

### 6.1 우선 테스트 항목

- 회원: 중복 아이디, 잘못된 로그인, 탈퇴 회원 로그인, 로그아웃 후 권한 차단
- 글: 작성자 외 수정/삭제 거부, 글 삭제 시 댓글·반응 연쇄 삭제
- 댓글: 부모 댓글/대댓글 조회, 삭제된 부모 표시, 권한 확인
- 반응: 최초 반응, LIKE↔DISLIKE 변경, NONE 복귀 거부, 집계 일치
- 검색/정렬: 제목 부분검색, 빈 결과, 동률, 빈 목록
- CSV: 빈 파일, 누락 필드, 금지 문자, 불러오기 후 관계 유효성
- UI: 로그인부터 글·댓글·반응·로그아웃까지 수동 시나리오

### 6.2 리스크 대응

| 리스크 | 대응 |
|---|---|
| 동적 메모리 오류 | 모듈별 init/free를 먼저 만들고 버퍼 1 사용 |
| CSV 관계가 깨짐 | 각 로드 단계 후 회원·글·부모 댓글·반응 참조를 검증 |
| raylib UI 지연 | 화면을 5개로 제한하고 UI는 C 코어 API 호출만 수행 |
| 힙/연결 리스트 학습 지연 | 인기 글 Top N과 연결 리스트 적용을 필수 완료 기준에서 제외 |
| 비밀번호 저장 구현 지연 | 원문 저장 금지 원칙을 유지하며 저장 정책을 독립 결정으로 기록 |
