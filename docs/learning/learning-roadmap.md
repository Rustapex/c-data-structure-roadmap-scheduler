# 자료구조(with C) 학습 로드맵

> 목표: C 자료구조를 직접 구현하고 raylib 기반 로컬 커뮤니티 시뮬레이터의 실제 기능에 적용한다.

## 1. 전체 학습 방향

학습은 개념 → 작은 구현 → 프로젝트 적용 → 테스트 → 기록 순서로 반복한다. Java 웹 개발의 엔티티·서비스 분리 감각은 활용하되, C에서는 포인터의 소유권과 malloc/free를 직접 책임진다.

~~~text
사용자 기능 정의 → 필요한 자료구조 선택 → C ADT 구현
→ 단위 테스트 → raylib 화면 연결 → 복잡도·메모리 기록
~~~

## 2. 프로젝트 적용 원칙

| 자료구조/개념 | 이번 프로젝트 적용 | 학습 포인트 |
|---|---|---|
| 구조체·열거형 | Member, Post, Comment, Reaction과 상태 값 | 데이터와 상태 규칙 분리 |
| 동적 배열 | 모든 엔티티 목록 | 확장, 삭제, 순회, 해제 |
| 부모 ID 기반 트리 | 댓글과 한 단계 대댓글 | 부모/자식 관계, 들여쓰기 조회 |
| 선형 탐색 | 아이디 중복, ID 탐색, 제목 검색 | O(n)을 받아들이는 MVP 기준 |
| 정렬 | 최신순, 반응 순 글 목록 | 비교 함수와 정렬 기준 |
| 힙/우선순위 큐 | 인기 글 Top N | 핵심 MVP 안정화 후 적용 |
| 연결 리스트 | 댓글 자식 목록 또는 독립 ADT 실습 | 배열과 삽입/삭제 비교 |
| 스택·큐·일반 그래프 | 2차 별도 학습 | 이번 커뮤니티 MVP에 억지 적용하지 않음 |

## 3. 저장과 보안 범위

- CSV는 DB 대신 데이터 지속성과 파일 입출력을 학습하기 위한 저장 형식이다.
- members.csv, posts.csv, comments.csv, reactions.csv를 우선 사용한다.
- 줄바꿈과 쉼표를 입력에서 금지해 MVP CSV 파서를 단순하게 유지한다.
- 비밀번호 원문은 파일·테스트 로그·문서에 남기지 않는다. 해시 저장 방식은 구현 전에 결정하며, 이 앱은 보안 인증 제품이 아니다.

## 5. 8/12~8/30 학습 순서

### 5.1 구조체, 포인터, 동적 배열 — 8/12~8/16

- MemberList, PostList의 init, append, find, remove, free를 설계한다.
- 아이디 중복 검사와 작성자 권한 검사로 포인터·구조체 전달을 연습한다.
- 배열 확장 전후 데이터 보존, 빈 목록, 중간 삭제를 테스트한다.

### 5.2 댓글 트리와 삭제 규칙 — 8/17

- parent_comment_id가 없는 댓글은 루트, 값이 있는 댓글은 대댓글으로 정의한다.
- 목록 순회로 루트 댓글과 자식 댓글을 계층 출력한다.
- 대댓글이 있으면 부모 본문을 삭제 표시로 바꾸고, 없으면 제거하는 규칙을 구현한다.

### 5.3 상태 전이와 집계 — 8/18

- ReactionStatus를 NONE, LIKE, DISLIKE로 정의한다.
- 반응은 취소하지 못하며 LIKE와 DISLIKE 사이에서만 변경한다.
- 글별 집계가 반응 목록과 일치하는지 테스트한다.

### 5.4 탐색, 정렬, 우선순위 큐 — 8/19 이후

- 제목 부분검색은 먼저 PostList 선형 순회로 구현한다.
- 최신순·반응 순 정렬을 구현하고 동률 기준을 문서화한다.
- 힙 기반 인기 글 Top N은 필수 기능이 안정화됐을 때만 연결한다.

### 5.5 파일 입출력과 CSV — 8/20~8/21

- fopen, fgets, fprintf와 반환 코드 기반 오류 처리를 학습한다.
- 불러오기 뒤 참조 무결성(작성자, 글, 부모 댓글, 반응)을 검증한다.
- 빈 파일, 잘못된 열 수, 존재하지 않는 참조를 테스트한다.

### 5.6 raylib UI — 8/22~8/24

- raylib의 창·텍스트·버튼·입력 처리만 필요한 범위에서 학습한다.
- 로그인/회원가입 → 글 목록/상세 → 작성/수정 → 댓글/반응 → 프로필/로그아웃 흐름을 만든다.
- UI는 도메인 데이터를 직접 바꾸지 않고 C 코어 API를 호출한다.

### 5.7 테스트·문서화·시연 — 8/25~8/30

- assert 기반 모듈 테스트를 우선 작성한다.
- 시간이 남으면 Unity Test Framework를 C 테스트 프레임워크로만 검토한다.
- 시간복잡도, 메모리 해제, UI 수동 시나리오를 문서화한다.

## 6. 2차 확장 학습

- 투표: Poll, PollOption, Ballot 구조체와 투표 변경 규칙을 별도 설계한다.
- 스택/큐/일반 그래프: 커뮤니티 핵심과 분리된 C ADT 학습 또는 팔로우 관계 확장에 사용한다.
- 해시 테이블: 아이디와 검색 단어의 빠른 조회가 필요해졌을 때 도입한다.
- Unity Engine: raylib MVP가 끝난 뒤 C 코어를 DLL API로 분리해 C# UI에서 호출하는 별도 프로젝트로 진행한다.

## 8. 최종 완료 기준

- 구조체, 포인터, 동적 배열과 해제 책임을 설명할 수 있다.
- 회원·글·댓글·반응의 자료구조와 업무 규칙이 실제 C 코드에 구현돼 있다.
- 댓글 계층, 제목 검색, 정렬, 반응 집계에 자료구조를 적용한 이유를 설명할 수 있다.
- raylib 화면이 C 코어 API를 통해 기능을 호출한다.
- 테스트 결과, 주요 연산의 복잡도, 메모리 관리 방식이 문서화돼 있다.
